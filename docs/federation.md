# 联邦

联邦(federation)让两个**各自独立部署**的 Lab Inventory 实例互相开放:A 实验室的人可以在自己的界面里浏览 B 实验室的资产,并直接发起借用申请。

它不是共享数据库,也不是同步复制。每个实例的数据始终留在自己这边,请求是实时转发过去的,而且授权范围精确到"哪个实验室对哪个实验室"。

## 什么时候用得上

- 同一栋楼里几个课题组各自部署了一套,想互相看看对方有没有现成的元件
- 合作单位之间需要偶尔借设备,但不愿意合并成一套系统、共用一个管理员

如果只是一个单位内部的多个实验室,**不要用联邦**——直接在同一个实例里建多个实验室就行,那样权限和检索都更顺。

## 概念

| 概念 | 说明 |
| --- | --- |
| 节点(node) | 一个部署实例。每个实例在初始化时生成一个永久的 `node_id` |
| 配对(pairing) | 两个节点交换共享密钥的一次性握手,用配对码完成 |
| 信任(trust) | "本实验室 → 对方某个实验室"的单向授权。配对是节点级的,信任是实验室级的 |
| 访客关联(guest link) | 远端用户在本地形成的影子账号,用于记录是谁借的 |

一次配对可以支撑多条信任:节点之间只需要握手一次,之后每对实验室各自决定要不要开放。

## 前置条件

- 两边都是**公网或双方网络可达**的地址,且都启用了 HTTPS
  联邦默认要求 `https://`(`federation.require_https`),并拒绝私网地址(`allow_insecure_private_network`)。这两条不建议为了图省事关掉:请求里带的是长期有效的共享密钥。
- 两边都设了正确的 `federation.public_base_url`——对方要按这个地址回连
- 两边都设了 `APP_FEDERATION__ENABLED=true`

在 `.env` 里:

```dotenv
FEDERATION_ENABLED=true
PUBLIC_URL=https://inventory-a.example.com
```

改完 `docker compose up -d`。

## 建立联邦

假设 A 实验室要开放给 B 实验室看。**两边都要有实验室管理员(lab_admin)账号**,系统管理员做不了这件事——联邦授权的是具体某个实验室,而系统管理员不属于任何实验室。

### 1. A 侧生成配对码

A 的实验室管理员登录 → **联邦** → **生成配对码**。

配对码是一次性的、有有效期的,用完即失效。通过可信渠道(当面、加密聊天)发给 B,**不要发在公开群里**——拿到它的人可以代表 B 完成握手。

### 2. B 侧建立信任

B 的实验室管理员登录 → **联邦** → **添加信任**,填:

- A 的实例地址(`https://inventory-a.example.com`)
- 刚才拿到的配对码

提交后,B 会主动回连 A 完成握手:双方各自生成并保存共享密钥,记下对方的 `node_id` 和 TLS 证书指纹。

### 3. 反向再来一次(如果需要双向)

上面建立的是**单向**的:B 能看 A。要让 A 也能看 B,把两边的角色对调再走一遍。

### 4. 验证

B 的用户在**资产**页面应该能切换到 A 的实验室,看到 A 的资产和库存。

## 远程借用

B 的用户在 A 的库存条目上点"借用",申请会转发到 A,出现在 A 的待审列表里。A 的管理员批准或驳回,结果回传给 B。

- 借用记录**存在 A 那边**——东西是 A 的,账也记在 A
- B 这边的用户在"我的借用"里能看到自己提交的申请和状态
- A 那边会为这个远端用户建一个影子账号(`is_federation_shadow`),用来标记是谁借的。同一个人多次借用会复用同一个影子账号

访客(guest)不能发起远程借用——远程借用走的是联邦代理,只对 lab_admin 和 user 开放。

## 协议怎么保证安全

每个跨实例的请求都带这些头:

```
x-federation-node-id            调用方的节点 id
x-federation-key-version        密钥版本
x-federation-timestamp          时间戳
x-federation-nonce              一次性随机数
x-federation-signature          HMAC-SHA256 签名
x-federation-remote-laboratory-id  代表哪个实验室发起
```

签名覆盖方法、路径、请求体哈希、节点 id、实验室 id、用户身份和时间戳。接收方会:

1. 按 `node_id` 找到共享密钥,重算签名比对
2. 检查时间戳在 `federation.request_ttl_seconds`(默认 300 秒)之内
3. 检查 nonce 没被用过(存在数据库里),防重放
4. 检查发起方声称的实验室对目标实验室**确实有一条 active 的信任**
5. 校验 TLS 证书指纹跟配对时记下的一致

任何一步不过就是 401/403。密钥换掉或信任撤销后,对方立即失去访问。

## 撤销

**联邦** → 找到那条信任 → **撤销**。立即生效,对方下一个请求就会被拒。

撤销的是信任(实验室级),节点之间的配对还在。要彻底断开,把该节点相关的所有信任都撤掉。

已经批准的历史借用记录不会因为撤销而消失——它们是本实验室的账。

## 排查

**添加信任报"无法连接到远端"**
- 检查 A 的 `PUBLIC_URL` / `federation.public_base_url` 是不是外部真的能访问到
- 从 B 的服务器上 `curl https://inventory-a.example.com/api/v1/health_check` 试试
- A 的证书要是被信任的 CA 签的,自签证书连不上

**报"配对码无效"**
配对码是一次性且有有效期的。重新生成一个。

**报 401,签名校验失败**
两边的时钟差太多会导致时间戳超出有效期。都开 NTP。

**能配对但看不到对方的资产**
配对只是节点级握手,还要有实验室级的信任。确认信任列表里那条是 active 的,并且方向对(是"我信任对方的哪个实验室")。

## 不开联邦

联邦是可选的。不用就在 `.env` 里:

```dotenv
FEDERATION_ENABLED=false
```

所有 `/federation/*` 接口会一律返回"Federation is disabled",界面上的联邦入口也不出现。
